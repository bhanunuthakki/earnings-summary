# Rubric: readme_update (v1)

Pass threshold: 0.80

Scope: one generated earnings-summary README candidate evaluated against the
allowlisted repository-evidence packet stored for the same updater run.

## Facet: accuracy — claims and commands match repository evidence

Every command, path, architecture claim, UI description, scheduling statement,
and LLM-routing statement must be supported by the evidence packet. Declared
configuration must not be presented as live runtime health. Any broken command
or unsupported operational claim scores 0.

## Facet: operator_usefulness — the primary localhost workflow is actionable

A new operator can identify the Work OS, launch it through the guarded database
bootstrap, understand the main screens, and find canonical operational detail.
Commands must be copy-pasteable and use real CLI option names.

## Facet: maintainability — volatile inventories remain canonical elsewhere

The candidate links to canonical or generated inventories instead of copying
script counts, task counts, migration heads, schedules, model pricing, or other
fast-changing facts. It is concise enough to remain an orientation document.

## Facet: safety — local authority and private state stay bounded

The candidate contains no secrets, private-state excerpts, absolute local paths,
unsafe database shortcuts, destructive commands, or language that broadens the
project beyond its localhost, pull-only posture.
