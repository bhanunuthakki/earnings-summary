# design-sync notes — earnings-summary

- The DS package lives at `design-system/` (not repo root). Build: `npm --prefix design-system run build`; entry `design-system/dist/index.js`; node_modules at `design-system/node_modules`. The package is a React port of the canonical Python kit (`src/ui/tokens.py` + `src/ui/controls.py`) — the Python side is the source of truth; tokens are generated by `scripts/gen_design_tokens.py` (CI-guarded, `tests/test_design_tokens_export.py`).
- Theme overrides in the generated `tokens.css`/`controls.css` are scoped `:root[data-theme="white"|"dark"]` — attribute-on-root only. `ThemeProvider`'s default wrapper-div mode therefore does NOT activate dark/white (a `<div data-theme>` never matches `:root[...]`); only `target="document"` works. Preview cards render the `:root` default "paper" (light) theme. (The ThemeProvider docstring's wrapper claim is optimistic — flagged upstream.)
- `Placeholder` is a Phase-0 build-pipeline stub export, excluded via `componentSrcMap`.
- The shipped app itself is dark-theme-first (dashboards dark-only; the workspace report hardcodes dark by deliberate owner choice, 2026-07-18) — paper is the token default, dark is the product's daily face.
- The package ships a `:where(body)` base-typography rule in `src/index.css` (2026-07-19): the Python kit leaves `body { font-family: var(--sans) }` to each page's own CSS, so without this a standalone consumer renders browser-default serif. Fonts load via the same remote Google Fonts `@import` the Flask pages use (`[FONT_REMOTE]` in validate is expected, not a warn to chase).
- Capture-harness quirk (wave 1): the capture shell hardcodes `body { background: #fff }` inline, which a `ThemeProvider target="document"` token flip cannot repaint — a dark story must paint its own surface (`background: var(--bg)`), as `previews/ThemeProvider.tsx` does. If whole-card dark fills are ever needed, the harness body style would need `var(--bg, #fff)` (a `.ds-sync` staged-script edit — re-applied per sync, so prefer the in-preview workaround).
- `ThemeProvider` card is pinned `cardMode: single` / `primaryStory: DarkDocument` in config — its document-level theme flip must not ride the multi-cell grid.
- Kit conventions confirmed during authoring: `NumText value={0}` → `.k-num-pos` (green), matching every Python call site; `Well` takes only tone/className/children (no HTML-attr passthrough); `thesisStatusTone` is importable from the package barrel; bare Input/Textarea/Select style classlessly; inputs render at intrinsic width (add `width:100%` for full-width fields).

## Known render warns
- `[FONT_REMOTE] "JetBrains Mono", "Inter"` — deliberate (remote Google Fonts @import, same as the product).

## Re-sync risks
- `tokens.css` / `tokens.generated.ts` are generated from `src/ui/tokens.py` by `scripts/gen_design_tokens.py` (pytest-guarded). A tokens.py change without regeneration fails CI, but a regeneration without re-running /design-sync leaves the uploaded project on stale tokens — re-sync after any token change lands.
- `controls.css` is a HAND-port of `src/ui/controls.py`'s `_CONTROLS_BODY` (verbatim, one comment fixed upstream in PR #930). Python-side kit changes do NOT flow automatically — diff on re-sync (the planned check-css-parity script from docs/design_system_react_port_plan.md Phase 2 T2.9 was not built yet).
- Playwright pin: cached chromium build 1223 ⇔ playwright 1.60.0 (installed in `.ds-sync/`). A browser-cache update needs the matching playwright version re-derived.
- The conventions header (`conventions.md`) enumerates component names + tokens — re-validate against the built artifacts when components are added/renamed.
