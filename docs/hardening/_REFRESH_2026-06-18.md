## The strategic fork: why multi-tenant L2 is the wrong target

Both lenses returned **`stay-single-user-harden-robustness`, high confidence.**

**Categorical hard-stops (no engineering resolves these):**
- **FMP Terms of Service** forbid redisplay of FMP data on any application "designed for utilization by multiple individuals … irrespective of whether such usage is complimentary or paid" without a separate, custom-quoted commercial Data Display & Licensing Agreement. This binds even a *free* beta on the shared key. (legal-1, critical)
- **Personal LLM billing can't be resold.** Today's spend rides the operator's Claude Pro/Max subscription (per `CLAUDE.md`). Multi-tenant COGS reverts to metered-API rates: ledger shows **~$3.68 per tracked name per month** ($468 over ~24 days, 3,281 calls). A 15–25 name tenant = $55–93/mo LLM *alone*, before the five-figure-class FMP license, payment fees, and support.
- **No per-tenant cost ceiling is possible** without the auth+tenancy work that doesn't exist (`llm_budget.py` caps are global-by-purpose; 93 routes, zero auth, zero rate-limit) — one tenant can invert margin for all.
- Plaid-derived cost-basis/P&L + third-party PII would trigger GDPR/CCPA the moment a second real user enters a system with no privacy program (no policy, no lawful basis, no subprocessor DPAs, no export/erase).

**No wedge:** the tool's shape (personal research aggregator + LLM briefs + alerts) matches none of the owner's own seven validated solo-operator wedges and competes with entrenched incumbents; zero willingness-to-pay signal in the repo.

**Kill criteria for the multi-tenant path (default = killed):** do not start the L2 rebuild unless ALL hold — (a) ≥3 named prospects with written willingness-to-pay above per-tenant COGS; (b) a written FMP commercial-redisplay quote that is economic at that scale; (c) the product re-shaped to a surviving wedge. If a pilot is ever attempted *without* a signed FMP license + executed DPAs — **stop**; that is the non-recoverable failure mode.

## L2 multi-tenant gate state (for completeness — DEFERRED, not actioned)

Real blockers that go live the moment a second tenant is admitted. **Dormant today** (single-user, loopback bind). Listed so the decision to defer is explicit, not accidental.

- **Identity/authZ:** no authN on any of 40+ routes (`authz-1`/`appsec-1`, critical); IDOR via `?user_id=` (`authz-2`/`appsec-2`, critical); no object-level ownership checks (`authz-5`).
- **Tenancy:** ~50 core tables no `user_id`, no enforced predicate (`tenant-data-layer-1`/`mt-1`, critical, XL); no per-request tenant context (`tenant-request-context-4`, critical); connection sprawl regressed to 143 `sqlite3.connect` across 101 files, no central choke point (`mt-2`, critical); on-disk artifacts + background jobs carry no tenant context (`tenant-ondisk-5`, `tenant-background-6`).
- **Ops:** no IaC/Dockerfile/deploy pipeline (`id-noiac`, critical, XL); no env separation (`id-env-separation`).
- **Legal:** FMP redisplay license (critical); no privacy policy / lawful basis (`legal-2`); no subprocessor DPAs (`legal-3`); no data-subject export/erase (`legal-4`).

## Recommendation

1. **Formally retarget "the next level" from L2-multi-tenant to L1+ single-user hardening.** Record the multi-tenant kill criteria above so the decision is durable.
2. **Execute Batch 1 immediately** (all S, data-loss + injection-persistence). WAL first.
3. **Then Batch 2** (LLM agency verification + supply-chain hygiene) — restores the spotlight-by-construction posture the audit credited and that recent PRs eroded.
4. **Batch 3** as a follow-on (local control-plane gating + observability).
5. **Stop the PII-to-Google-Drive backup** or document/accept it explicitly; it is the owner's own data but it silently left the box.

The multi-tenant L2 stack stays deferred-by-design behind the kill criteria — revisit only if the owner's goal changes from "best personal CIO for me" to "build a company," and then evaluate a wedge-fit artifact as a *fresh* idea, not as a retrofit of this codebase.
