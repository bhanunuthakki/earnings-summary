# Backend / ingestion procedure retirement inventory

Read-only source inventory at `d19bc3e3`. No application/test edits, live state, collection, model calls or runtime-use measurement. Existing tests are evidence references, not newly executed checks. Counts below describe bounded candidate retirements, not work already safe to delete. Source searches establish callers, not operational non-use.

## Current production routes

- **IR acquisition:** `discover_ir_documents_all._run_one` shells into `fetch_ir_documents.py`; `fetch_ir_from_urls.register_urls` also calls its `process_ticker`. This loose-manifest route downloads into ticker staging, writes a URL sidecar and shells into `categorize_ir_uploads.py`. The latter classifies/moves/registers files and updates the legacy document index. The separate `manage_issuer_document_sources.py` already exposes prepare/validate/publish over `fetch_ir_documents.prepare_issuer_document_sources` and `pipeline.managed_ir_sources.publish_prepared_issuer_documents`.
- **Document interpretation:** `process_document_evidence.py` → `provenance.document_evidence_pipeline` drains deterministic capture/fulltext debt with per-item outcomes and a database-bound cursor. Morning manifest stage `stage_0d1_document_evidence` calls it. `process_ir_documents_state.py` → `process_ir_documents.py` instead reads the JSON index, calls narrative LLMs and writes summary files/processed flags. These implement different DAG stages; neither is a drop-in replacement for the other.
- **Numeric extraction:** `extract_kpis_from_summaries.py` reads generated narrative outputs through two jobs in `compute.kpi_extract_summaries`. `extract_kpis_from_ir.py --capture` already exposes original-PDF capture from that same module; `--apply` accepts explicit source-document manifests. `refresh_ir_kpis.py` independently discovers/downloads/parses spreadsheet numbers and calls `ir_pipeline.ingest.ingest_spreadsheet_kpis`.
- **FMP facts/native publication:** bulk `extract_facts.py`, `pipeline.quarterly_refresh` and the immutable-corpus branch in `refresh_cache.py` call the same statement extractors. Their financial writes use existing compute/persistence/restatement owners. `foreign_normalization_run.normalize_foreign_sources` and `population_source_facts.populate_source_fact_plane` then publish bounded native graphs through `SourceFactRepository`; the repository does not parse source documents or replace acquisition authorization.

## Boundaries and recommendation

Start with the **FMP family consolidation**. It replaces one complete active batch procedure without first solving missing source semantics or changing persisted models. Resolve the zero/OK error masking explicitly; keep the ordered income-before-segment dependency. The next highest structural targets are original-source numeric extraction and managed registration, once their missing input/coverage contracts are demonstrated.

Do not add another attempt, inventory, cache or publication store. Existing `pipeline.run_accounting` owns logical fingerprints/attempts; `document_evidence_pipeline`/fulltext owners own deterministic source processing; managed IR owns prepared publication/recovery; `SourceFactRepository` owns native immutable graph publication. Their different receipts prove different properties. A narrow public operation can absorb an old procedure; a new framework is unnecessary.

No physical legacy fact-table/module retirement is authorized by this inventory. `directives/data_provenance.md` §11 requires strict reader/writer audits across two quarterly cycles and one annual cycle, followed by separate approval/migration/rollback proof. Preserve immutable source bytes, observations, unknown/novel values, admission states and historical reconstruction. Keep the eight logical DAG stages; remove duplicate executions and alternate authority, not the stage semantics. Before any deletion, perform the required transitive production reachability scan and update actual scheduler/UI/CLI callers. No candidate here is declared runtime-unused.
